# 待补接口规划

版本：v1.0-draft  
状态：接口规划，当前不一定已实现  

本文档用于提前定义后续服务端需要补充的接口，避免客户端开发被接口不确定性阻塞。

当前已实现接口以 `docs/mock-server-api.md` 为准。本文档只列目前缺少或后续建议补充的接口。

## 1. 通用约定

需要登录的接口统一使用：

```http
Authorization: Bearer <token>
```

普通请求和响应使用 JSON：

```http
Content-Type: application/json
Accept: application/json
```

错误响应沿用当前统一格式：

```json
{
  "code": "INVALID_REQUEST",
  "message": "请求参数不正确"
}
```

## 2. 优先级说明

| 优先级 | 说明 |
|---|---|
| P0 | 近期应优先补齐，避免阻塞客户端主链路 |
| P1 | 建议补齐，用于完善交互 |
| P2 | 后续扩展，用于增强演示和答辩完整度 |

## 3. Tab 管理接口

当前已有：

```text
GET    /tabs
GET    /tabs/catalog
GET    /tabs/{tabId}
POST   /me/tabs
DELETE /me/tabs/{tabId}
POST   /tabs/validate
POST   /tabs/{tabId}/actions/{actionId}
```

当前缺少的是“创建、修改、删除用户自定义 Tab”的接口。

### 3.1 创建用户自定义 Web Tab

优先级：P0

```http
POST /tabs
Authorization: Bearer <token>
```

作用：

```text
创建一个新的用户自定义 Tab。
第一版只建议支持 entryType=web。
创建成功后默认启用到当前用户。
```

请求：

```json
{
  "id": "custom-docs",
  "displayName": "我的文档",
  "description": "用户自定义网页 Tab",
  "icon": "docs",
  "route": "/custom-docs",
  "entryType": "web",
  "entryUri": "https://example.com",
  "minContainerVersion": 1
}
```

响应：

```json
{
  "success": true,
  "tabId": "custom-docs",
  "tab": {
    "id": "custom-docs",
    "displayName": "我的文档",
    "description": "用户自定义网页 Tab",
    "icon": "docs",
    "route": "/custom-docs",
    "entryType": "web",
    "entryUri": "https://example.com",
    "version": {
      "major": 1,
      "minor": 0,
      "patch": 0
    },
    "minContainerVersion": 1,
    "permissions": [],
    "enabled": true,
    "sortOrder": 100
  }
}
```

校验规则：

```text
id 不可为空
displayName 不可为空
route 不可为空，且必须以 / 开头
entryType 第一版必须是 web
entryUri 不可为空，建议必须是 http:// 或 https://
同一个用户下 route 不应重复
```

错误示例：

```json
{
  "code": "INVALID_TAB_CONFIG",
  "message": "自定义 Tab 第一版仅支持 web 类型"
}
```

### 3.2 修改用户自定义 Tab

优先级：P1

```http
PUT /tabs/{tabId}
Authorization: Bearer <token>
```

作用：

```text
修改用户自定义 Tab 的名称、描述、入口地址等配置。
不建议允许修改系统内置 Tab。
```

请求：

```json
{
  "displayName": "我的文档",
  "description": "更新后的网页入口",
  "icon": "docs",
  "entryUri": "https://example.com/new-docs",
  "sortOrder": 100
}
```

响应：

```json
{
  "success": true,
  "tab": {
    "id": "custom-docs",
    "displayName": "我的文档",
    "description": "更新后的网页入口",
    "icon": "docs",
    "route": "/custom-docs",
    "entryType": "web",
    "entryUri": "https://example.com/new-docs",
    "version": {
      "major": 1,
      "minor": 0,
      "patch": 0
    },
    "minContainerVersion": 1,
    "permissions": [],
    "enabled": true,
    "sortOrder": 100
  }
}
```

错误示例：

```json
{
  "code": "FORBIDDEN",
  "message": "系统内置 Tab 不允许修改"
}
```

### 3.3 删除用户自定义 Tab

优先级：P1

```http
DELETE /tabs/{tabId}
Authorization: Bearer <token>
```

作用：

```text
删除用户自定义创建的 Tab。
区别于 DELETE /me/tabs/{tabId}：
- DELETE /me/tabs/{tabId} 是停用当前用户的 Tab
- DELETE /tabs/{tabId} 是删除自定义 Tab 配置本身
```

响应：

```json
{
  "success": true,
  "tabId": "custom-docs"
}
```

错误示例：

```json
{
  "code": "FORBIDDEN",
  "message": "系统内置 Tab 不允许删除"
}
```

### 3.4 批量调整我的 Tab 排序

优先级：P2

```http
PUT /me/tabs/order
Authorization: Bearer <token>
```

作用：

```text
调整当前用户已启用 Tab 的展示顺序。
```

请求：

```json
{
  "items": [
    {
      "tabId": "approval",
      "sortOrder": 10
    },
    {
      "tabId": "custom-docs",
      "sortOrder": 20
    }
  ]
}
```

响应：

```json
{
  "success": true
}
```

## 4. AI OnCall 会话接口

当前已有：

```text
GET /oncall/stream?message=...
```

当前缺少：

```text
会话创建
会话列表
消息上传
消息记录拉取
指定会话流式响应
```

如果客户端只做第一版流式问答，可以继续用当前 `GET /oncall/stream`。如果要做聊天记录和多轮会话，建议补以下接口。

### 4.1 创建 AI 会话

优先级：P1

```http
POST /oncall/sessions
Authorization: Bearer <token>
```

作用：

```text
创建一个 AI OnCall 会话。
客户端进入 AI 页面时可以创建会话，后续消息归属于该 sessionId。
```

请求：

```json
{
  "title": "Tab 接入咨询"
}
```

响应：

```json
{
  "sessionId": "sess-001",
  "title": "Tab 接入咨询",
  "createdAt": "2026-05-31T12:00:00+08:00"
}
```

### 4.2 获取 AI 会话列表

优先级：P2

```http
GET /oncall/sessions
Authorization: Bearer <token>
```

作用：

```text
获取当前用户历史 AI OnCall 会话。
```

响应：

```json
[
  {
    "sessionId": "sess-001",
    "title": "Tab 接入咨询",
    "createdAt": "2026-05-31T12:00:00+08:00",
    "updatedAt": "2026-05-31T12:10:00+08:00",
    "messageCount": 4
  }
]
```

### 4.3 上传用户消息

优先级：P1

```http
POST /oncall/sessions/{sessionId}/messages
Authorization: Bearer <token>
```

作用：

```text
客户端发送用户消息。
服务端保存消息，并返回 messageId。
```

请求：

```json
{
  "content": "如何接入一个审批 Tab？",
  "contentType": "text"
}
```

响应：

```json
{
  "messageId": "msg-001",
  "sessionId": "sess-001",
  "role": "user",
  "content": "如何接入一个审批 Tab？",
  "contentType": "text",
  "createdAt": "2026-05-31T12:01:00+08:00"
}
```

### 4.4 获取会话消息记录

优先级：P1

```http
GET /oncall/sessions/{sessionId}/messages
Authorization: Bearer <token>
```

作用：

```text
拉取某个 AI OnCall 会话的历史消息。
```

响应：

```json
[
  {
    "messageId": "msg-001",
    "sessionId": "sess-001",
    "role": "user",
    "content": "如何接入一个审批 Tab？",
    "contentType": "text",
    "createdAt": "2026-05-31T12:01:00+08:00"
  },
  {
    "messageId": "msg-002",
    "sessionId": "sess-001",
    "role": "assistant",
    "content": "接入审批 Tab 时，客户端需要先支持 native route。",
    "contentType": "text",
    "createdAt": "2026-05-31T12:01:05+08:00"
  }
]
```

### 4.5 指定会话流式响应

优先级：P1

```http
GET /oncall/sessions/{sessionId}/stream?messageId=msg-001
Authorization: Bearer <token>
Accept: text/event-stream
```

作用：

```text
基于某条用户消息生成 AI 流式回复。
```

SSE 响应：

```text
event: delta
data: {"text":"接入业务 Tab 的第一步是定义 TabManifest。"}

event: tool
data: {"name":"validate_tab_config","status":"完成","summary":"已检查协议字段、权限声明、版本约束和入口类型。"}

event: done
data: {"messageId":"msg-002"}
```

### 4.6 删除 AI 会话

优先级：P2

```http
DELETE /oncall/sessions/{sessionId}
Authorization: Bearer <token>
```

响应：

```json
{
  "success": true,
  "sessionId": "sess-001"
}
```

## 8. 建议实现顺序

建议按以下顺序补接口：

```text
1. POST /tabs
2. PUT /tabs/{tabId}
3. DELETE /tabs/{tabId}
4. GET /debug/permissions
5. POST /oncall/sessions
6. POST /oncall/sessions/{sessionId}/messages
7. GET /oncall/sessions/{sessionId}/messages
8. GET /oncall/sessions/{sessionId}/stream
9. 审批/日程列表与详情接口
```

当前最优先的是：

```text
POST /tabs
```

因为它可以支撑客户端“添加一个用户自定义 Web Tab”的功能。
